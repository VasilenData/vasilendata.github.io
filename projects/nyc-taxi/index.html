What the failure tests prove

The current publisher validates a candidate, then replaces eight consumer tables and their version metadata in one DuckDB transaction.

  • Invalid candidate: mismatched counts or mart totals are refused; the previous consumer relations remain unchanged. Validation test
  • Interrupted copy: injected exceptions during copying or before commit preserve every previous consumer relation. Rollback test
  • Abrupt process exit: reopening the database finds the previous release intact; a subsequent valid publication succeeds. Crash-and-recovery test

These are controlled tests with generated candidates and sample integration data. The system runs locally, in Docker and in CI. It is a single-writer warehouse; full-data publication overhead has not been remeasured, and no live cloud mart is claimed.
