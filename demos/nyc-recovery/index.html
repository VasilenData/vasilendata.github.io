The engineering decision
Validation is necessary, but it does not make a sequence of table replacements atomic. Keep candidate data separate, validate inside the publication transaction, then commit all eight tables and the version metadata together.
  • Observed failure: without the transaction, the reopened fact table contained 7 rows while the hourly mart still represented 4.
  • Observed recovery: with the transaction restored, all 9 consumer relations matched the previous version. A retry published 7 fact rows and 7 mart trips.
  • Trade-off: copying tables adds storage and runtime overhead. This uses one DuckDB database and one writer; consumers spanning several queries need a read transaction.
This exercise does not establish power-loss durability, multi-writer behavior, cloud operation, customer adoption or independent human review. It is separate from the project's 31.6M-row historical benchmark.
