Evidence, not a production claim

Three failures worth being able to explain.

Run a bounded exercise, inspect what changed, and check what stayed valid. These are local portfolio demonstrations with saved reports and explicit limits.

Start with the result; reproduce when you want to go deeper. Commands run from each repository root after installing its pinned requirements. Use fresh output paths. Database exercises require disposable infrastructure; they are not migrations to run against a working service.

01 / Meterwork · Python, PostgreSQL, FastAPI

A lost response must not become a second charge.

Problem: one worker can commit an event and disappear before its caller receives success. Process-local quotas also multiply when more workers are added.

Implementation: shared PostgreSQL admission and a durable event identity. The exercise observes a committed event, kills that exact worker before the response arrives, and retries against the survivor.

Observed: the retry is a duplicate; seven events, 77 units and 19,250 microUSD reconcile exactly once. A separate bounded local workload completed 350/350 requests across two workers. That is an offered workload, not a maximum-capacity result.

02 / NYC Taxi · Dagster, dbt, DuckDB

A failed refresh must preserve the last valid release.

Problem: replacing reporting tables before all checks pass can expose a partial or corrupt dataset.

Implementation: build and validate a candidate, publish all eight reporting tables together, then check the consumer state independently.

Observed: a 30,000-row historical replay rejects a deliberately corrupt candidate, preserves all eight consumer tables and their metadata, and records local incident and recovery receipts. This is separate from the earlier 31.6M-row measurement.

03 / Finance Mart · dbt, SQL, DuckDB, PostgreSQL

One report must not mix two releases.

Problem: renaming a metric can break consumers, and several queries through mutable views can straddle a successful promotion.

Implementation: keep the v1 model contract, add an explicit v2, validate frozen candidate tables and atomically promote the consumer views and pointer. Multi-query consumers pin one immutable release schema before reading.

Observed: both local adapters pass the same 14-check migration exercise: rejected candidate, interrupted promotion, rollback and a historical close rebuilt from frozen sources. A two-connection check pauses a reader across promotion and confirms it retains its complete original release.
