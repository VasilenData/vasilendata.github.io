Update, delete, recover

  • Collection/path identities remain stable while source and chunk hashes change with content.
  • Unchanged files reuse postings; changed documents and deletions commit together.
  • A labelled synthetic interruption after writes and before commit preserved the old snapshot for an independent reader.
  • Malformed documents, excessive input, scope changes and unconfirmed empty collections fail closed.

Scope

  • Four documents; not a large messy production corpus or full dense/reranker evaluation.
  • Local UTF-8 text/Markdown/HTML/JSON only; PDF/OCR, authentication and remote crawling are not implemented.
  • SQLite transaction safety within one local index; no distributed durability or concurrent source-writer guarantee.
  • No LLM generation or external API calls; CPU/storage costs are not priced.
